# A+B 整合训练包：先读我

本包已修改 A 的 train.py，实际接入 B 的 build_training_bundle，不是只有 B 的模块。
A 基础版本 de53102，B 来源 973ffaa；整合修改为本次本地工作区版本，尚未提交或推送 Git。B 源模块保持原样；其交接文档中的“待接入”描述是来源历史，本包接入已完成。

## 安全放置

先解压到新文件夹（例如 C:/glaucoma_competition/AB_integrated），不要覆盖旧 code 或 outputs。
打开 Anaconda Prompt，激活原来训练成功的环境，再进入解压包的 code 目录。
不需要重新安装 torch/CUDA，也不包含数据和训练权重。
如果缺 yaml，只安装：python -m pip install -r requirements-extra.txt

## 第一步：检查

在 code 目录执行：
python -m unittest discover -s tests -v
预期 13 项通过。本包云端已通过；仍需在你的实际 Python 3.11 / GPU 环境确认。

## 第二步：小流程验收

将 configs/windows-smoke.example.yaml 另存为 configs/smoke.local.yaml，确认 data_root 是实际官方数据目录；output_dir 必须选不存在的新实验目录。首次设 num_workers=0，batch_size=8。
python -m src.train --config configs/smoke.local.yaml --selftest
python -m src.train --config configs/smoke.local.yaml --train-batches 2 --epochs 1

第二条只训练两批，但会对完整 valid 评估，避免只抽到一个类别使 AUROC 无效。初次建目录索引和完整 valid 推理可能需要等待。这是从随机初始化做流程自测，不可当作正式效果对照；不触碰测试集，不用于官方提交。已有同名训练产物会拒绝覆盖，重试换新 output_dir；不要删除原正式训练产物。

## 第三步：正式 B2 参考基线（需要重新训练时才执行）

将 configs/windows-baseline.example.yaml 另存为 configs/baseline.local.yaml，确认数据路径，使用全新的输出目录。
python -m src.train --config configs/baseline.local.yaml

默认 ResNet18、ImageNet 预训练、224、seed42、10 epoch、batch64、AMP、无增强、data_strategy=pos_weight（B2），与 A 原基线条件对应。首次 worker=0 为兼容性选择；可在验收后改到本机已验证的8。若显存不够降低 batch，但这改变了实验条件，需如实登记，不声称严格复现原结果。固定相同 batch 和预算再做策略对照。
无需为了首次官方提交重新训练：现有 ep8 best.pt 可以等 C 的推理/校验工具就绪后继续用。本包也没有新增正式 infer.py。

## 后续对照

配置 data_strategy 可为 bce / pos_weight / oversample / focal / undersample；augmentation.augment 独立控制增强。
不要额外加入冲突的旧 pos_weight 开关，不要把过采样叠加到加权 BCE。
configs/b-data-experiments.json 是六组计划，tools/prepare_b_experiments.py 可生成配置；尚无正式效果结论，优先 B0-B3，每组使用独立输出目录。
