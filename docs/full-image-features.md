## 运行

在 Windows PowerShell 中执行：

```powershell
# 在已激活 Python 环境的仓库根目录运行；数据路径替换为自己的目录。
python -X utf8 -u scripts/extract_image_features.py --data-root 'D:\path\to\glaucoma_first' --output-dir outputs/image-features --workers 4
```

使用本机 Python，直接读 D 盘，减少跨 Docker 挂载的目录访问开销。数据与图像处理版本会记录在 report.json 中，后续使用相同环境恢复。需要安装的 NumPy/Pillow 在此环境已具备；不用在容器里重新安装。

不要添加 `--limit-per-split`，该参数只供小范围验证。默认提取完整训练、验证、测试的 63,100 张图片。

## 你会看到什么

```text
[load] train: checking CSV and filenames...
...
[resume] 0/63100 reused; 63100 images to extract
[features] 50/63100; reused=0; errors=0; ETA=... min
...
RESULT: COMPLETE; 63100/63100; errors=0
```

目录核对结束后，每完成 50 张或约 5 秒输出/保存一次进度；当前几张图尚未处理返回时可能稍有间隔。ETA 根据本次实际速度动态估算，开头不稳定。试跑外推的约 48 分钟是串行特征耗时粗估，不是四线程完整任务的完成时间承诺。

`--workers 4` 表示最多同时处理 4 张，使用 CPU 和内存，不需要 GPU。若内存紧张，可暂停后改为 `--workers 2` 恢复；改变 worker 数不改变特征定义。

## 中断与恢复

- 优先在终端按 Ctrl+C，让脚本保存已处理结果后退出。
- 重启电脑或容器不影响写到本地的缓存；运行完全相同的命令继续。
- 数据路径、大小、修改时间及 Python/NumPy/Pillow 版本和特征实现未变时才复用缓存。若怀疑源文件内容被改但元信息保留，用新输出目录重新计算。
- 非正常断电最多可能丢掉最近未提交的一批结果，重跑时重新计算；不要求手工删缓存。
- 同一输出目录只允许一个任务，第二份会报占用错误。`run.lock` 文件可以保留；操作系统在进程结束后释放锁，不需手动删文件。
- 不要把数据或缓存文件夹上传到 GitHub。

## 输出文件

位于项目 `outputs/image-features/`：

| 文件 | 用途 |
| --- | --- |
| progress.json | 当前阶段、计数、复用数、错误数、速度和预计剩余时间 |
| feature-cache.sqlite3 | 恢复用特征缓存，正式扫描不另存数万张缩略图 |
| features.csv | 完成后导出的逐图指纹、尺寸、亮度、对比度等 |
| report.json / report.md | 最终范围、状态、版本和结果 |
| errors.json | 失败或扫描期间发生变化的文件清单 |

只有最后 `status=COMPLETE`、`scope=full`、成功数 63,100、错误为空才表示本轮全量提取完成。`COMPLETE_SAMPLE` 表示仅小范围验证通过。若 `INCOMPLETE`，先核查错误，不自动删图或改标签。

CSV 中 `dhash64` 按字符串读取，保留前导零。其余特征与试跑共用同一函数：先按 EXIF 调整方向，等比例缩为不超过 256×256，再计算灰度统计和 64 位水平差分指纹；灰度统计包含黑边。
