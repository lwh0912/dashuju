# 队员 B：图像特征小样本试跑

## 本轮目标

训练、验证、测试各抽 30 张，共 90 张，固定种子 2026。训练和验证样本尽量各含 15 张阴性、15 张阳性；这仅为检查两类流程是否可运行，样本阳性占比不代表原始分布。

每张图片只读，生成不超过 256×256 的 RGB 缩略图；转换灰度后计算平均亮度、像素标准差和暗像素比例，并提取一个 64 位 dHash（差分视觉指纹）。

该指纹用于后续筛选候选，不能单独确认重复，不具备裁剪/旋转不变性。亮度统计包含图像黑边，只描述缩略图，不给医学质量结论；本轮不设自动删除阈值。

## 你怎么操作

使用本机已验收的 Anaconda 环境执行，避免容器跨 Windows 目录的文件元数据开销。容器 NumPy/Pillow 也已通过接口和合成测试；后续同一次正式指纹提取应固定一种环境并记录版本，避免混用不同 Pillow 版本的特征缓存。

PowerShell 命令：

```powershell
# 在已激活 Python 环境的仓库根目录运行；数据路径替换为自己的目录。
python -X utf8 -u scripts/pilot_image_features.py --data-root 'D:\path\to\glaucoma_first' --per-split 30 --seed 2026 --output-dir outputs/image-feature-pilot
```

本次助手已实际试跑，结果以本地 report.json 为准；如只是查看结果，不必再次运行。同一配置重跑会覆盖该试跑目录中的同名报告。

参数：

- `--data-root`：本机原始数据位置。
- `--per-split 30`：每个划分抽取 30 张，不是每类 30 张。
- `--seed 2026`：相同数据及配置下抽取相同样本。
- `--output-dir`：所有报告和缩略图的本地输出目录。

## 结果如何阅读

打开 `outputs/image-feature-pilot/report.md`，确认状态 PASS、成功 90/90、错误 0。

用 VS Code 查看 `outputs/image-feature-pilot/contact-sheet.jpg`：应看到三行（train/valid/test 各五张）等比例缩略图。原图未被缩小覆盖，缩略图是另存的副本。

`features.csv` 主要字段：

| 字段 | 含义 |
| --- | --- |
| split / image_name / label | 数据集、原始图片标识、标签；测试样本无标签 |
| width / height | 应用 EXIF 方向后的图像尺寸 |
| dhash64 | 16 位十六进制字符串，表示 64 位指纹；读表时按字符串保留前导零 |
| brightness_mean | 灰度缩略图平均像素值，范围 0–255 |
| contrast_std | 灰度缩略图像素标准差；越大只表示像素离散更明显 |
| dark_fraction_below_10 | 灰度小于 10 的像素比例，含眼底照片黑边 |
| feature_seconds | 单张读取、解码、缩放与特征提取耗时，不含缩略图文件写入 |

目录与 CSV 核对耗时单独记录。小样本均时外推只用于初步规划，不包含全量候选检索、缓存及所有输出开销，受图像尺寸、类别抽样和系统缓存影响，不是准确 ETA。

## 完成标准与后续

本轮只确认“选样—读取—生成特征—保存结果—统计耗时”链路可用，没有对全部图片执行近重复搜索，也不依据这 90 张宣称全数据无近重复。

下一阶段再安排：带进度和恢复缓存的全量特征提取；跨训练/验证的候选检索与人工复核；必要时引入对缩放、裁剪等变换更合适的方法。近重复阈值应通过人工复核校准，不直接套用固定距离删图。

缩略图和逐图明细属于比赛数据衍生产物，仅留在本地或赛事允许的团队存储，不上传到 GitHub。
