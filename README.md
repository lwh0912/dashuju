# 2026 全国高校计算机能力挑战赛 · 大数据挑战赛

本仓库用于整理第八届全国高校计算机能力挑战赛“大数据挑战赛”的赛题解读、备赛计划与后续实验记录。

项目操作入口：[本地环境与数据检查](docs/getting-started.md) · [三人协作流程](docs/team-workflow.md)。

当前代码提供 CSV/图片对应检查、文件名大小写兼容读取和环境检查；完整训练与预测流程尚待实现。个人数据路径填入 `configs/paths.local.json`（从示例复制），本地报告输出到 `outputs/`，均不上传到仓库。

队员 B 已补充精确查重、可恢复的图像特征提取、近重复候选与方法校准、数据画像工具及合成测试，详见[数据审计交接](docs/data-audit-handoff.md)。近重复与患者重叠仍未排除，工具不自动删除图片或改标签。

**比赛任务：根据眼底照片预测青光眼阳性概率；排名首先看 AUROC，只有 AUROC 相同时才比较 AUPRC。**

> 本说明依据比赛规程及官方赛项页面整理，核对日期为 2026 年 10 月 13 日。比赛要求如有更新，以组委会最新通知、参赛平台及所在省赛区规定为准。下文明确区分官方要求、备赛建议与待确认事项。

## 1. 赛题与目标

构建眼底图像二分类模型，对测试集每张图片输出属于青光眼阳性的概率。

| 标签 | 含义 |
| --- | --- |
| `1` | 青光眼阳性，规程包括确诊或疑似病例 |
| `0` | 青光眼阴性 |

赛题强调在类别极度不平衡的条件下识别少数阳性样本、减少漏诊，同时保持整体区分能力。

## 2. 数据集

| 数据划分 | 图片数量 | 标签与用途 |
| --- | ---: | --- |
| 训练集 | 51,396 | 有标签，用于训练 |
| 验证集 | 5,849 | 有标签，用于调参和模型选择 |
| 测试集 | 5,855 | 用于最终评测，生成提交结果 |

- 图片为彩色眼底照片，格式为 JPG/PNG。
- 尺寸不固定，拍摄设备和光照条件存在差异。
- 文档提到年龄等辅助临床信息；各数据划分实际提供的字段需下载后检查。
- 阳性比例极低，但规程未给出具体比例，应分别统计训练集和验证集的类别分布。

## 3. 评分规则与解读

### 官方规则

| 指标 | 排名作用 | 关注点 |
| --- | --- | --- |
| **AUROC** | 主要指标，优先排序 | 不同阈值下的整体区分能力 |
| **AUPRC** | 仅在主要指标相等时二次排序 | 精确率与召回率的关系，关注少数阳性类 |

**每天最多提交 2 次。**

### 对备赛的影响

- 优先按验证集 AUROC 选择模型，同时记录 AUPRC、召回率和精确率。
- 提交连续概率，保留模型对样本的区分信息；不要把概率列转换成二值标签。
- 只调整分类阈值、保持概率分数不变，不会改变 AUROC 或 AUPRC。
- 准确率不能单独反映不平衡数据上的效果。例如，假设阳性占 1%，全部预测阴性也能获得 99% 准确率，但会漏掉所有阳性。这里的比例仅用于举例。
- 本地 AUPRC 计算方式应与官方评测一致；PR 曲线积分与 Average Precision 不应默认视为同一种实现。

指标说明参考：[scikit-learn 官方文档](https://scikit-learn.org/stable/modules/model_evaluation.html#roc-metrics)。

## 4. 提交要求

### 提交内容

- 初赛：测试集预测结果 CSV 文件。
- 复赛：预测结果 CSV 文件及模型，供主办方验证。

### 文件格式

文件名为 `submission.csv`，编码为 **UTF-8**，包含以下三列：

```csv
Image_name,Probability,Pred_Label
test_00000.jpg,0.92,1
test_00001.jpg,0.12,0
```

| 字段 | 含义 |
| --- | --- |
| `Image_name` | 测试集图片文件名，必须与实际文件名一致 |
| `Probability` | 青光眼阳性概率，范围为 `[0,1]` |
| `Pred_Label` | 预测类别，`1` 为阳性、`0` 为阴性，规程默认阈值为 `0.5` |

以上文件名和数值仅为格式示例。若下载包或参赛平台提供官方模板，应按模板进一步核对。

### 提交前检查清单

- [ ] 每张测试图片都有且只有一条结果；按实际测试集核对总行数。
- [ ] 文件名及扩展名准确，没有重复或遗漏。
- [ ] 概率位于 `[0,1]`，不存在空值、NaN 或无穷值。
- [ ] 标签仅包含 `0` 和 `1`，并与所采用的阈值一致。
- [ ] 列名大小写准确，没有额外的 DataFrame 索引列。
- [ ] 文件名、编码和 CSV 分隔符符合平台要求。
- [ ] 保存本次提交对应的模型、训练配置和验证指标。

## 5. 模型与运行环境约束

### 规程列出的服务器环境

| 项目 | 配置 |
| --- | --- |
| GPU | NVIDIA T4 16GB × 1 |

| 内存 | 32GB |

| Python | 3.12 |
| 推理框架 | PyTorch 2.10.0 + torchvision 0.25.0 |

### 硬性限制

- **模型文件压缩前总大小 ≤500MB。**
- **单张图像端到端延迟 ≤100ms。**

模型大小、输入分辨率、多模型融合及多次增强推理均应结合这些限制评估。初赛仅交 CSV，也应提前考虑后续模型验证。

规程列出服务器配置，但没有明确承诺向每支队伍免费提供训练算力；训练资源安排需另行核实。

### 实验原则

1. 先完成可运行、可复现的完整流程，再增加模型复杂度。
2. 验证集尽量保持原始类别分布，避免验证成绩失真。
3. 若提供患者编号，检查不同数据划分间是否存在同一患者；不要擅自改变官方评测划分。
4. 数据不平衡处理方法应通过验证实验选择，不预设某一种方法必然更好。
5. 每次尽量改变一个主要因素，记录配置、随机种子、指标和运行成本。
6. 使用本地验证筛选候选方案，合理安排每日两次提交机会。
7. 保存模型权重、代码版本、环境说明及推理方法，便于复赛验证。
